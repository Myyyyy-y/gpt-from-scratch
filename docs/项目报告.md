# GPT-from-scratch 项目总结

> 对标 Stanford CS336 Assignment 1 的从零实现项目。
> 本文档为最终总结，所有数字以最终实验为准（消融与训练技术验证均已收官）。

## 一、项目范围

项目覆盖 **分词器 → 数据管线 → 模型 → 训练栈 → 采样推理 → 推理加速 → 消融实验**
的完整流程；所有核心组件手写实现，未使用 `nn.Transformer`、`tiktoken`、
`torch.optim.AdamW`、`F.scaled_dot_product_attention` 等高阶 API。

### A. 组件实现

**分词器（纯 Python，仅依赖 regex）**
- 字节级 BPE 训练（256 基础字节 + 特殊 token；增量式合并优化：倒排索引 + 增量计数）
- encode / decode / save / load 全流程；单词级缓存加速语料编码
- GPT-2 官方预分词正则；decode 先拼字节再解码，避免多字节字符被截断

**模型（LLaMA 式，手写 forward）**
- RMSNorm / LayerNorm（上转 fp32 保证数值稳定性）、SwiGLU / GELU-MLP（手写 erf 精确式）
- RoPE（cos/sin 表 `persistent=False`，按绝对位置查表）
- 数值稳定 softmax、因果注意力（掩码对角线偏移统一 prefill/decode）
- **组件开关**：norm_type / ffn_type / pos_type，构成消融实验的架构基础

**训练栈（全部手写）**
- AdamW（解耦权重衰减、动量估计、偏差修正、norm/bias 不衰减、绑定参数去重）
- warmup + cosine 学习率调度、全局范数梯度裁剪、logsumexp 交叉熵（fp32）
- bf16 混合精度、checkpoint 断点续训（含优化器状态）、JSONL 日志逐行 flush

**采样与推理**
- temperature / top-k / top-p（向量化 nucleus：sort → cumsum → 掩码右移）
- KV cache：先 RoPE 后拼接、位置由缓存长度推断；prefill / decode 两阶段

### B. 数据管线

- TinyStories 全量：train 4.67 亿 token（212 万篇）/ valid 469 万 token
- 流式下载（HF 镜像）→ 训练 BPE（vocab 8192）→ 32 进程并行编码 → uint16 memmap
- 内置解码回读校验；压缩率 4.25 bytes/token

## 二、消融实验

### LR sweep（29M，四组并行，唯一变量 max_lr）

| lr | best val loss | 现象 |
|---|---|---|
| 3e-4 | 1.4467 | 收敛稳定，欠拟合 |
| **1e-3** | **1.3832** | 最优 |
| 1.25e-3（参考项目 H 的最优值） | 1.3964 | 与 1e-3 同处最优区间 |
| 3e-3 | 2.2837（发散） | val 反弹至 3.9，gnorm ~50 |

结论：最优 lr 位于 1e-3 附近的平坦区间；发散组完整留档。

![LR sweep 四组对比](../assets/lr_sweep.png)

### 位置编码消融（rope / learned / none，29M + lr 1e-3）

| pos_type | best val loss |
|---|---|
| **rope** | **1.3832** |
| learned | 1.4071 |
| none | 1.4259 |

结论：RoPE 最优，与既有研究结论一致。learned 与 none 差距仅 0.019，表明短上下文
（256 token）下可学习绝对位置编码未提供有效增益，RoPE 的相对编码带来稳定收益。
none 组在无位置信息下仍达 1.4259，说明因果掩码本身携带一定的顺序线索。

![位置编码三组对比](../assets/pos_ablation.png)

## 三、KV cache：收益受模型规模限制的推理优化

**正确性**：逐 token 等价性测试（贪心解码下，cache 与无 cache 输出完全一致）。

**实测加速比**：

| 环境 | 16M | 29M |
|---|---|---|
| GPU（bf16） | 1.04× | 1.05×（复测，52.29 → 54.79 tok/s） |
| CPU（fp32） | 1.63× | 1.76× |

加速比低于参考项目的 2.49×，原因分析：

1. 小模型 + 短序列下，GPU 每步耗时由 kernel 启动开销（约 12ms）主导，
   cache 节省的计算（约 0.1ms）占比过小；
2. CPU 上计算为真正瓶颈，cache 消除的重复计算直接转化为加速（1.63×）；
3. 加速比随模型规模上升（16M→29M：1.63→1.76），与理论预期一致——
   KV cache 的收益在大模型上充分体现。
