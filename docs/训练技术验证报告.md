# 训练技术验证报告

> 在自研 from-scratch 框架上复现并验证 2024–2025 年前沿训练技术。
> 每项技术以"架构开关 + 对照实验"的形式验证。
> 参考来源：modded-nanogpt speedrun 社区、Moonlight（Muon is Scalable）、
> Gemma3 / Qwen3 / OLMo2 技术报告。

## 一、QK-Norm：抑制高学习率发散

### 背景

LR sweep 中 lr=3e-3 组发散：val loss 由 2.28 反弹至 3.9，梯度范数出现最高约
**22000** 的尖峰（experiments/004）。

![梯度范数发散对比](../assets/gnorm_divergence.png)

发散组尖峰密集（最高约 22000）；QK-Norm 组（橙色）全程平稳。

### 方法

QK-Norm（Gemma3 / Qwen3 / OLMo2 的标准组件）：注意力打分前对 Q、K 分别执行
RMSNorm，约束注意力 logits 的数值尺度。实现为 `src/model.py` 中的 `qk_norm`
开关（约 10 行）。

### 结果

| 组 | best val loss | 现象 |
|---|---|---|
| lr 3e-3 裸跑 | 2.2837（发散） | val 反弹至 3.9，gnorm ~50 |
| **lr 3e-3 + QK-Norm** | **1.4020** | 全程稳定，gnorm ≤ 0.4 |
| 参考：最优组（lr 1e-3） | 1.3832 | — |

图 `assets/qknorm_rescue.png` 对比发散曲线与修复后曲线：

![QK-Norm 修复发散](../assets/qknorm_rescue.png)

蓝色 = lr 3e-3 裸跑（发散）；橙色 = lr 3e-3 + QK-Norm（修复后全程贴近最优组曲线）；
绿色 = 最优组（lr 1e-3）。

### 结论

1. **QK-Norm 可消除高学习率发散**：lr 3e-3 由不可用变为接近最优组水平
   （1.4020 vs 1.3832）。
2. **干净归因**（experiments/012_qknorm_clean）：初始 QK 组 min_lr=3e-4
   （max/10），与最优组 min_lr=3e-5 不一致，存在混淆变量。在其余配置与最优组
   完全一致的重跑中，QK-Norm 得到 **1.3746 < 1.3832**（-0.0086），确认其在
   最优学习率下具有真实收益；此前"QK 未超最优组"的结论系混淆所致，予以修正。

## 二、Muon vs AdamW

### 背景

Muon（Jordan 2024）：对矩阵参数更新方向执行 Newton-Schulz 正交化（奇异值
均衡化），替代 AdamW 的逐元素步长调整；2025 年经 Kimi K2 在万亿参数规模验证。

### 实现与发现

- 手写 Muon（约 60 行，`src/train.py`）与 HybridOptimizer：Muon 负责隐藏层矩阵，
  AdamW 负责 embedding/lm_head，与 modded-nanogpt 的分工一致
- **v1 复现 Moonlight 报告的原始现象**：缺少 weight decay 时约 5000 步后权重
  无约束增长导致发散（gnorm ~194）
- v2 补充 decoupled weight decay，并对双侧 lr 施加同步调度（Muon 侧同样采用
  warmup/cosine），即 experiments/009_muon_wd

### 结果

| 组 | best val loss | 备注 |
|---|---|---|
| AdamW 最优组（003，lr 1e-3） | 1.3832 | 基准 |
| **Muon v2** | **1.3716** | 优于 AdamW 0.0116 |

图 `assets/muon_vs_adamw.png` 对比 Muon v2 与 AdamW 最优组全程曲线
（蓝色 = Muon v2；橙色 = AdamW 最优组）：

![Muon vs AdamW](../assets/muon_vs_adamw.png)

结论：补充 decoupled weight decay 后，Muon v2 消除 v1 的发散，并在
29M / 28500 步设置下小幅优于手写 AdamW（1.3716 vs 1.3832）。
v1 发散留档（gnorm ~194）即 Moonlight"Muon 需要 weight decay"现象的复现。

## 三、ReLU²

speedrun 社区验证的 FFN 激活简化：`relu(x)²` 替代 GELU/SwiGLU，效果接近且
计算开销更低（SwiGLU 需 3 个线性层，ReLU² 仅需 2 个）。中期（step 9000）
持平或略优；最终与最优组差距较小（experiments/011_ffn_relu2）。

### 结果

| 组 | best val loss | 备注 |
|---|---|---|
| SwiGLU 最优组（003，lr 1e-3） | 1.3832 | 基准 |
| **ReLU²** | **1.4083** | 落后 0.025，节省约 1/3 FFN 参数与计算 |

图 `assets/ffn_relu2.png` 对比 ReLU² 与 SwiGLU 最优组全程曲线
（蓝色 = ReLU²；橙色 = SwiGLU 最优组）：

![FFN: ReLU² vs SwiGLU](../assets/ffn_relu2.png)

结论：ReLU² 全程接近 SwiGLU 曲线，最终差距 0.025（SwiGLU 略优）。
以约 2/3 的 FFN 计算量获得相近效果，可纳入技术组合实验。

## 四、2-epoch 重训

最优配置（29M + lr 1e-3）训练 2 epochs（57000 步），检验数据重复利用的
边际收益（experiments/010_best_2epoch）。

### 结果

| 指标 | 数值 |
|---|---|
| best val loss | **1.3212**（@56000，较 1-epoch 最优组 1.3832 提升 0.062） |
| final val loss | 1.3631（第二圈末期回升，轻微过拟合） |

图 `assets/2epoch_vs_1epoch.png` 对比 2-epoch 与 1-epoch 最优组全程曲线
（蓝色 = 2-epoch；橙色 = 1-epoch 最优组）：

![2-epoch vs 1-epoch](../assets/2epoch_vs_1epoch.png)

结论：数据重复利用带来约 0.06 的提升；best 出现于 56000 步而 final 回升 0.042，
表明第二圈末期出现过拟合，早停可获得最优结果。

## 五、技术组合与单项消融

单项实验完成后补充的组合与消融（experiments/012_*，29M / 28500 步 / lr 1e-3）：

| 组 | 配置 | best val loss | 结论 |
|---|---|---|---|
| 最优组（003） | 基线 | 1.3832 | 基准 |
| **QK-Norm 干净归因** | 最优配置 + qk_norm | **1.3746** | 真实收益（-0.0086），修正第一节旧结论 |
| 输出投影零初始化 | 最优配置 + zero_init_proj | 1.3933 | 无增益，默认关闭 |
| untie 权重绑定 | 最优配置 − tie | 1.3823 | 与基线持平（增加 4.2M 参数，无收益） |
| 技术组合 | QK+Muon+ReLU²+untied+zero-init | 1.3900 | 无协同增益，需分别调优各技术 |

结论：QK-Norm 与 Muon 单独有效（1.3746 / 1.3716 均优于最优组），但全叠加未产生
协同增益（1.3900），提示组合实验需先统一各技术的超参量纲（Muon 侧 lr 与
AdamW 侧不一致）。

## 六、最终结果

- **归一化消融**（013_layernorm）：LayerNorm best 1.3817 vs RMSNorm 1.3832，基本持平
- **数据量消融**（013_data_3m）：3M token 严重过拟合，best 2.31@750，final valid ~4.72
- **AttnRes 训练与幅值分析**（013_attnres）：best 1.3793 vs 最优组 1.3832，基本持平；
  幅值对比见 `assets/magnitude_comparison.png`
- **多 seed 显著性**（最优组 seed 1/2/3）：best val 均值 **1.3771 ± 0.0108**
  （单次 1.3668 / 1.3761 / 1.3883；对照 seed=0 最优组 1.3832）
- **29M GPU 版 KV cache 复测**：RTX 4090 / bf16 下 52.29 → 54.79 tok/s（**1.05×**），
  验证小模型 GPU 上收益受 kernel 启动开销限制（见 `docs/kv_cache测试.md`）

## 附录：实验失误与修正记录

以下记录实验过程中的真实失误与修正方式，作为方法学留档。

### 数据管线与工程

| 失误 | 现象 | 根因与处理 |
|---|---|---|
| Embedding 初始化与权重绑定冲突 | 初始 loss 高达 273 | 默认初始化尺度与 tied weights 不匹配，logits 尺度失控；统一初始化并进行端到端校验（初始 loss 应接近 ln(vocab)≈9.0） |
| CPU 上 autocast 报错 | 训练脚本在 CPU 下崩溃 | torch CPU autocast 仅支持 bf16；CPU 路径跳过 autocast（见代码注释） |
| HF split 命名不一致 | 验证集 loss 异常偏高 | 数据集 split 名 `valid`/`validation` 不统一，tokenization 使用不一致的 vocab/merges；统一命名并通过 decode 回读校验 |
| 空 corpus 复用 | 缓存命中时静默读取空语料 | 缓存逻辑缺少非空校验；补充保护 |
| transformers 版本冲突 | tokenizer/数据集 API 行为漂移 | 锁定环境版本并留存 `pip freeze` |
| data3m 训练中断 | 训练进程被终止 | 共享服务器上被其他进程误杀；tmux + `--resume`（含优化器状态）恢复 |
| uint16 溢出风险 | token id 存储 | vocab 8192 远低于 65535，仍需确保 id 不超 uint16 上限（见代码注释） |
| plot_magnitude 越界 | 幅值分析脚本报错 | 误将 token 索引作为 token id 查询 embedding；补充边界检查 |

### 训练实验

| 失误 | 现象 | 结论 |
|---|---|---|
| lr 3e-3 裸跑发散 | val 反弹至 3.9，gnorm 峰值约 22000 | 高学习率边界条件完整留档，构成 QK-Norm 实验的动机 |
| QK-Norm 组 min_lr 混淆 | 一度得出"QK 无收益"的结论 | 原 QK 组 min_lr=3e-4、最优组 3e-5，混入第二个变量；干净归因（012_qknorm_clean）后确认真实收益 1.3746 |
| Muon v1 缺少 weight decay | 约 5000 步后 gnorm ~194 | 复现 Moonlight 报告现象；补充 decoupled weight decay 后 v2 优于 AdamW |
| LayerNorm 中间快照误判 | step 5250 时看似明显落后 | 最终 1.3817 vs 1.3832 持平；收敛性结论应基于终值，中间态不具备外推性 |
| KV cache 加速比未达 2.49× | 小模型 GPU 上仅 1.04~1.05× | 收益被 kernel 启动开销（约 12ms）稀释；计算占比随模型规模上升，大模型才进入收益区间（见 `docs/kv_cache测试.md`） |
| AttnRes 不支持 KV cache | 推理对比受限 | 实验前确认功能交集；评估脚本对不支持 cache 的变体采用无 cache 路径 |
